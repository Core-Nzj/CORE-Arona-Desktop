# CORE Arona Desktop

Windows向け、ユーザーが所有するMMDモデルをローカルで表示するデスクトップアバターホストです。

## Phase 1: アバターだけを表示するデスクトップマスコット

- 背景が透明な最前面ウィンドウにPMX / PMDモデルを表示
- モデルを読み込めたら上部バー・ファイル名ラベルを含む常設UIをすべて非表示
- キャラの右クリックで、macOS風のダークな独立カスタム操作パネル（ホーム／音声／表情／診断）を開く。
- キャラ上のホイールで拡大・縮小
- キャラを左ドラッグしてウィンドウを移動
- WebGL描画結果の透明度を約5px単位で採取し、Windowsのウィンドウ形状をキャラの輪郭に近い複数矩形へ変換。透明部分は背後のアプリにクリックが通る
- 再起動時に前回のモデルを復元
- モデル未設定・読み込み失敗時は「モデル選択」・「終了」ボタンを表示

## FRAME UI方針（2026-10-29）

従来のブルーアーカイブ風装飾は廃止し、Apple/macOSに着想を得たオリジナルUIへ統一します。操作パネル、初期モデル選択画面、音声設定画面はダークグレーを基調とし、Graphite `#0e0e0e`、Carbon `#1d1d1f`、Steel `#333336`、Porcelain `#f5f5f7`、Apple Blue `#0071e3` を使用します。優先フォントはSF Pro Text（未導入環境はInter / Segoe UI等にフォールバック）です。

右クリックパネルは既存のタブ・操作・タイトルバードラッグ・フォーカスアウト動作を維持します。外観はmacOS風ですが、ウィンドウの閉じるボタンはWindows式の右上「×」（ホバー時は淡い赤）です。実装の参考資料はProjectソースの `DESIGN.md` / `tokens.json` / `variables.css`。Apple公式の画像・アイコン・フォント実体は同梱しません。

### FRAME操作パネルのサイズと表示倍率

- 四辺・四隅（計8方向）の端を左ドラッグすると、パネルの縦横サイズを変更できます。透明ウィンドウのElectron標準リサイズ制約を回避するため、画面座標を使った独立のリサイズ処理を用います。
- 最小サイズは300×320px。リサイズは操作中のディスプレイの作業領域内に制限されます。
- パネルにフォーカスした状態で `Ctrl + +` または `Ctrl + =` で中身の表示倍率を上げ、`Ctrl + -` で下げます。`Ctrl + 0` で100%に戻します（75〜150%）。
- パネルのサイズと表示倍率は、Windowsのユーザーデータ領域の `frame-panel-layout.json` に保存され、次回表示時に復元されます。MMDアバターのカメラ倍率や音声設定への影響はありません。
- パネルを離れてフォーカスが外れた場合と、右上の「×」またはEscでは、従来どおりパネルを閉じます。

## 必要なもの

- Windows 10/11
- Node.js 22.12以降（Node.js 24 LTSを推奨）、npm
- 個人利用を含め、用途に応じた利用許諾がある .pmx / .pmd とテクスチャ一式

## 起動方法

1. リポジトリをクローン（初回のみ）:
   `git clone https://github.com/Core-Nzj/CORE-Arona-Desktop.git`
2. リポジトリのディレクトリで `npm install`
3. `npm start`
4. 初回画面の「モデル選択」からPMX/PMDファイルを選択

すでにクローン済みなら、リポジトリで `git pull` して `npm start` を実行してください。

## 操作

| 操作 | 動作 |
| --- | --- |
| モデルを左ドラッグ | デスクトップ上の位置を移動 |
| モデルを右クリック | カスタム操作パネル（ホーム／音声／表情／診断） |
| 操作パネル上部のタイトルバーをドラッグ | 操作パネルの位置を移動 |
| モデル上でマウスホイール | 拡大 / 縮小 |
| 右クリック → ホーム → モデルを変更 | 別のPMX / PMDを選ぶ |
| 右クリック → ホーム → リセット | 初期倍率 |
| 右クリック → ホーム → アプリを終了 | アプリ終了 |

右クリックの操作パネルは、クリック透過するアバター本体とは別の小型Electronウィンドウで描画します。これにより、モデルの輪郭判定を維持しながらメニューを確実にクリックできます。Esc・右上の×・他ウィンドウへのフォーカス移動で閉じます。画面端では表示位置を補正します。メニューの各ボタンはElectronの制限付きIPCでのみ実行されます。

モデルの輪郭以外の透明部分では背後のアプリをクリックできます（約5pxの精度・縁に余裕あり）。モデルの選択・読み込みに失敗した場合は操作用パネルが現れます。

## モデルとライセンス

- 第三者のモデル、テクスチャ、音声、モーションはGitや配布パッケージに含めません。待機モーションはアプリ内でオリジナルのVMDデータを生成します。
- 各利用者がローカルのPMX / PMDモデルを選択します。
- 実際に利用するモデルや音声の規約に従ってください。
- 前回選択したモデルパスだけElectronのuserData/settings.jsonにローカル保存します。素材の送信や複製はしません。

## Phase 2-1: 待機モーション（2026-10-26）

ユーザーがモデルを選択すると、アプリ内でオリジナルの短いVMD待機モーションを生成します。モデルの骨や表情に直接書き込む改造は不要です。

- 両腕を下ろした自然な立ち姿（標準ボーン名「左腕」「右腕」等）
- 上半身の緩やかな4秒周期の呼吸と、小さな首・頭の動き
- 「まばたき」または「Blink」モーフがある場合に数秒おきに自動でまばたき
- 約12秒のループ。モデル変更時には旧アニメーションを解放
- 動く輪郭に追従するため、5Hzでクリック領域の更新を行う

初回は手元の実機で `git pull` → `npm start` として、Tポーズから腕が下がるか、目を閉じるかを確認してください。アニメーション初期化に失敗してもモデル表示は維持する設計です。

現在はモデルによって肩の軸・腕の向きが異なることを考慮した自動補正はありません。腕が不自然になった場合は、モデル別の姿勢設定を追加する方針です。

## Phase 2-1 不具合調査（モーションが動かない場合）

モデルの右クリック、透明当たり判定、ドラッグ、ホイール操作はPhase 1の実装を維持しています。モーションの実機動作は現時点で未確認です。

雨衣モデルでMMDランタイムが正常動作し、約4秒おきのまばたきと骨8本のモーション再生を実機確認しました。一方、手が背中側に回る姿勢だったため、肩のZ軸回転を従来の左右73度から50度に抑え、ひじのひねりを小さくしました。モデルの元姿勢がAポーズである場合も考慮した控えめな初期値です。腕の自然さは実機で再評価が必要です。

## Phase 2-2: 表情・感情制御（2026-10-26）

既存の透過ウィンドウ・右クリック・ホイール・ドラッグ・生成VMDによる呼吸とまばたきを維持したまま、表情モーフを切り替える機能を追加。

- キャラを右クリック → 「表情」 → 「通常／笑顔／怒り／悲しみ／驚き」を選択。
- モデルの既存モーフ名を自動解決（日本語名・英語名の候補に対応）。未対応の表情はメニューで選択不可。
- 感情の切り替えは約0.22秒の指数補間。通常へ戻すと表情が自然に消える。
- モデル変更時は古いモデルの表情状態を破棄し、新モデルで再判定する。
- 「表情診断」で実際に見つかったモーフ名を確認できる。
- 待機VMDが使用する「まばたき」、将来の口パクに使う「あ・い・う・え・お」などには触れない。
- 内部の `EmotionController.select(id)` を外部AIや音声連携から再利用できるように設計（外部通信自体は未実装）。

対応モーフがない場合は、キャラや待機モーションを壊さず、その表情だけ無効になる。新しい素材・リグへの対応は `src/emotions.mjs` の候補名を追加する。感情名は `neutral`, `happy`, `angry`, `sad`, `surprised`。

## Phase 2-3: VoiSona Talk（ローカル音声）

Electronアプリ側に `VoiSona Talk Proxy` と直接接続する音声エンジンを追加しました。Chrome拡張とは独立した機能であり、拡張機能の起動・停止・連携は必要ありません。VoiSona製品・音声データ・認証情報は同梱もGit登録もしません。

### 準備

1. 購入済みのVoiSona Talkを起動し、設定からREST APIを有効にします（標準127.0.0.1:32766）。
2. 開発版では **Python 3.11+** と `voisona-talk-proxy` のインストールが必要です。以前インストール済みなら何もする必要はありません。未導入の場合は `py -m pip install voisona-talk-proxy`。
3. `git pull`、`npm start` でデスクトップアバターを起動します。アプリが `127.0.0.1:32777` のProxyを自動起動し、既存Proxyが起動済みならそちらを再利用します。Proxyを別途手動起動する必要はありません。
4. キャラ右クリック → **音声（VoiSona Talk）→ 接続設定・認証情報...** からVoiSona Talkの登録メールとAPI用パスワードを設定します。これはアカウントログイン用パスワードではありません。

### 操作

- キャラ右クリック → **音声（VoiSona Talk）** → **接続・音声一覧を更新**。
- **使用する音声** から雨衣などインストール済みの音声ライブラリを選択。
- **テスト発話** で短い日本語の音声を合成して再生。
- **再生停止** で発話を中断。新しい発話は古い音声を中断する設計です。
- **音声診断** でProxyへの接続状況、使用ライブラリ、最後の再生エラーを確認できます。
- 音声が利用できなくても3Dモデル・呼吸・まばたき・表情・ドラッグ・輪郭判定は動作します。

### 実装上の安全対策

- 接続はElectronメインプロセスから固定のlocalhostのみ。Rendererから外部URLは指定できません。
- WAVのRIFF/WAVEヘッダーとサイズ上限（16 MiB）をチェックします。テキストは最大500文字。
- 新しいリクエストでは以前のWAV合成をAbortControllerで中断します。
- 音声ライブラリ名は通常のElectronローカル設定に保存。VoiSonaのユーザー名・APIパスワードは、Electronの `safeStorage` を使用しWindowsのDPAPIで暗号化した別ファイル（`userData/voisona-credentials.dat`）に保存します。暗号化できない環境では平文保存せずエラーにします。パスワードはRendererへ再送信せず、localhostのProxyにHTTP Basic認証で渡します。秘密情報とWAVはGitに入りません。

### 現在の範囲

**まずデスクトップ単体での音声合成・再生を確認する段階**です。外部テキストの受信と口パクは未実装です。Chrome拡張とは独立して動作します。

参照資料：VoiSona Talk Proxy https://pypi.org/project/voisona-talk-proxy/ ・ VoiSona Talk公式REST API https://manual.voisona.com/ja/talk/pc/2b6e9bc7efb180ea86ccc6c7347e9ca6

### 2026-10-27: WAV再生互換性修正

Proxy接続と音声ライブラリの取得は成功する一方、WindowsのElectronで「Failed to load because no supported source was found.」となる事例がありました。

- 発話WAVのヘッダーを読み取り、対応するPCM 8/16/24/32bit、IEEE float 32/64bit、WAVEFORMATEXTENSIBLE形式を、標準16-bit PCM WAVに正規化します。
- `<audio>`とBlob URLでWAVを読み込む実装を廃止し、変換した16-bit PCMをWeb AudioのAudioBufferに直接転送します。
- サポート外のWAV形式は、無言の再生失敗ではなく、形式番号とビット深度を含む診断エラーとして報告します。
- 右クリック → 「音声（VoiSona Talk）」 → 「音声診断」で入力WAV形式と再生状態を確認できます。
- 接続先は従来どおり `127.0.0.1:32777`。Chrome拡張との連携や共存調整は行っていません。

この修正はコード上のフォーマット変換・静的チェックを伴いますが、Windows上の実発話は先生の実機で再検証してください。


## 2026-10-27: VoiSona Proxy自動管理・認証設定

- アプリ起動時に `GET http://127.0.0.1:32777/health` を確認し、Proxyが動いていなければインストール済みPythonの `py -m voisona_talk_proxy --host 127.0.0.1 --port 32777` を子プロセスとして自動起動します。
- Chrome拡張用のProxyをすでに起動していても、それを再利用します。自動起動したProxyのみアプリ終了時に停止し、外部起動したProxyは停止しません。
- キャラ右クリック → **音声 → 接続設定・認証情報...** でメールアドレスとAPI用パスワードを入力し、「暗号化して保存・接続確認」。保存済みならパスワード空欄で変更せず維持できます。「認証情報を削除」も利用可能です。
- 保存時はWindows `safeStorage` により、メールアドレスとパスワードの両方を暗号化します。設定画面で暗号化データから平文パスワードを取り出して表示する機能はありません。秘密情報はGitに入らず、ブラウザや外部サービスに送信されません。
- パスワードはProxy起動引数・環境変数に設定せず、音声一覧・合成リクエストのHTTP Basic認証ヘッダーとしてメインプロセスからlocalhostに送信します。既存Proxyの認証設定がある場合も、設定画面で指定した認証を優先します。
- **現時点での内蔵は「Python Proxyのプロセス管理とGUI設定」**です。配布用インストーラーにPython実行環境を同梱する完全スタンドアロン化は未実装。VoiSona Talk本体と音声ライブラリは引き続き利用者がインストールして起動する必要があります。
- 接続診断・音声ライブラリのエラーは設定画面に表示。Proxy未導入でも3D表示、クリック操作、モーション、表情は独立して動きます。

## Google パスワードマネージャー / iCloud パスワードで認証情報を入力する

Electronの設定ウィンドウ自体は、Chromeに保存されたGoogleパスワードやiCloud Passwordsのブラウザー拡張を共有しません。そのため、右クリック → **音声（VoiSona Talk）→ 接続設定・認証情報...** → **ブラウザーでパスワード入力（Google / iCloud）** を用意しています。

1. アプリから既定のブラウザーで、3分間だけ有効な `http://127.0.0.1:32778/credentials/<ランダムトークン>` を開く（32778番が使用中なら別ポート）。
2. ChromeならGoogleパスワードマネージャー、WindowsのiCloud Passwords拡張機能を有効化したChrome/Edge/FirefoxならAppleのパスワードを利用可能。以前保存したパスワードの「サイト」がこのローカルアドレスと異なる場合、自動入力候補は表示されないことがあるため、パスワードマネージャーから検索してコピー・貼り付けする。初回手動入力後にブラウザーの保存機能を利用すれば、次回候補が出る可能性がある。
3. 送信すると同じWindows PC上のElectronメインプロセスで `safeStorage` 暗号化保存し、元の設定画面も自動更新される。入力完了後はブラウザーを閉じてよい。
4. iPhoneの「パスワード」をWindowsで使うには、Apple公式の **iCloud for Windows** と、利用ブラウザー用の **iCloud Passwords 拡張**のセットアップが必要。Windows版アプリや拡張機能が使えない場合はApple端末で確認して手動入力する。

セキュリティ：入力ページはIPv4ループバック `127.0.0.1` のみで公開し、256bit乱数トークンをURLのパスに使用する。さらに独立した256bitのフォーム内CSRFトークンを検証し、POST形式・ホスト・本文サイズを制限する。OriginやFetch Metadataヘッダーはブラウザー・拡張機能によって変化するため、認証条件には使用しない。JavaScriptなどの外部リソースなし、ブラウザーキャッシュなし、有効期限3分、成功後は1回限り。パスワードをURLやGitHubに書き込まない。ブラウザーのパスワード保存はブラウザー側の機能であり、本アプリから既存パスワードを直接読み出すことはない。

参考：Google パスワードマネージャー https://passwords.google/ ／ Apple iCloud パスワード for Windows https://support.apple.com/ja-jp/guide/icloud-windows/icw2babf5e03/icloud

### 2026-10-27: 一時ブラウザーフォームの送信拒否修正

### 2026-10-27: Chromeで「送信元が一致しません」が出る場合

Chromeや拡張機能等により`Origin`/`Sec-Fetch-Site`が期待値と異なる場合、従来は正しいフォームも拒否していました。現在はその値に依存せず、同一PCのみからアクセスできる一時URL（256bit）とHTMLフォーム内の独立した256bit CSRFトークンの双方で認証します。フォームの有効期限、1回限りの利用、内容検証、Windows暗号化保存は維持します。再起動後に新しいブラウザー入力ページを開いてください。

## Phase 2-4: ChatGPT回答 → VoiSona発話 → MMD口パク（2026-10-27 / 初期実装）

デスクトップアプリから、ブラウザーの新しいChatGPT回答を音声合成し、音量に応じてMMDモデルの「あ」モーフを動かせるようにしました。

2. Chromeの `chrome://extensions` で「デベロッパーモード」を有効にして「パッケージ化されていない拡張機能を読み込む」を選択。リポジトリの `browser-extension` フォルダーを指定します。

- Chrome拡張は新規ユーザー発言後に生成されたアシスタント回答だけを検出し、停止ボタンが消え、文章が約1.35秒変化しなかったとき送信します。過去の回答は読まない設計ですが、ChatGPTのHTML構造が変わると検出を修正する必要があります。

- 口パクはVoiSonaの音声波形（音量）から算出する簡易方式で、音素ごとの「あ・い・う・え・お」切り替えではありません。モデルに「あ」等の対応モーフがない場合は動かさず、音声だけ再生します。
- 自動連携は初期状態でOFF。モデル・VoiSona本体・ChatGPTのログイン情報等を拡張機能に含めません。Chrome拡張は自動配布されないため、各利用者がローカルで読み込みます。

`npm test` では口パクのモーフ制御とローカル受信口の認証・入力長制限を検査します。
Windows実機での音量追従、ChatGPT DOM検出、既存のクリック透過・ドラッグ・表情と併用した動作は追加検証が必要です。

### 2026-10-28: Chrome拡張のタブ別自動読み上げ（v0.8.0）

拡張機能のポップアップで「新しい回答の自動読み上げ」を次の3モードから選択できます。

- **全部ON**: すべてのChatGPTタブの新規回答を自動読み上げ。
- **選択タブのみ**: 開いているChatGPTタブを一覧表示し、チェックした1個または複数のタブだけ自動読み上げ。最初に切り替えたとき、未選択なら現在のChatGPTタブを1個選択。
- **全部OFF**: どのタブからも新しい回答を自動読み上げしない。

自動読み上げの許可は**タブ単位**です。同じタブで別会話を開いても許可が引き継がれます。別タブは個別に選択できます。F5のページ更新では維持し、タブを閉じるとそのタブの許可を削除します。モード自体はブラウザー再起動後も保持し、選択済みタブIDは再起動時に破棄して誤ったタブIDへ許可が移らないようにします。

許可済みタブから新しい回答の音声が実際に届いた場合のみ、再生中の音声から切り替えます。無許可タブの新規回答・F5・閉鎖によって、ほかのタブの音声が止まることはありません。**モードの切り替え自体では再生中の音声は停止しません。** 即座に止めたい場合は「停止」ボタンを押します。手動の「最後の回答を読む」「選択部分を読む」「試聴」は自動読み上げ許可とは独立して動作します。

Chromeへの読み込みに必要な権限として、ChatGPTドメインのホストアクセスを追加しました（ほかの閲覧サイトには不要）。アップデート時にChromeが追加権限の承認を求める場合があります。`git pull` → `chrome://extensions` で拡張を再読み込み → 対象ChatGPTタブをF5で更新して新しいポップアップから選択します。

```text
         └─ （各 .vmd ファイル）
```

- アバターを右クリック → **モーション** タブを開く。サブフォルダも含めてVMDが一覧に並びます。
- **一覧のVMDをクリック**：1回プレビューします。**前へ／次へ** でも切り替えられます（短いポーズは最低3秒表示）。
- **この動きを待機に設定**：選択したVMDを繰り返し再生する待機モーションにします。FRAME再起動時やモデル変更後も自動復元します。
- **待機モーションへ戻す**：プレビューを途中で止め、現在設定中の待機モーションへ戻します。
- **標準待機に戻す**：カスタム待機設定を解除して、FRAME従来の生成VMD（呼吸・まばたき）へ戻します。
- **フォルダを指定**：リポジトリとは別の任意のフォルダを選択できます。**一覧を更新**：追加したVMDを再読み込みします。

保存内容はWindowsのElectron `userData/settings.json` にあるモーションフォルダのパスと、選択したVMDの**相対パスのみ**です。VMDファイルそのものはコピー・アップロード・Git登録されません。フォルダを移動した場合はもう一度指定してください。

注意：この段階の待機は**選んだVMDの単純ループ**です。短いエモートを待機にすると同じ動作を繰り返します。プレビューから待機へ戻る際の高度なモーションブレンド、まばたきの常時重ね合わせ、自動エモート挿入はまだありません。別モデルでボーンが一致しない場合は診断から確認してください。Windows実機での待機復元・ループは引き続き確認が必要です。


### 2026-10-31: デジタルボディ転送演出（試作）

モーション切り替え時の姿勢ジャンプを隠すため、`Babylon.js` の描画キャンバスを一時的に2Dキャンバス上の細い断片とシアン色の走査光へ変換する演出を追加しました。追加のnpmパッケージ・画像・GIFは不要です。

- プレビュー／次へ・前へ／カスタム待機への切り替え／プレビュー終了後の復帰時、**現在のVMDを再生したまま約0.23秒でボディが消失**します。
- 完全に見えなくなってから新しいVMDの先頭へ移り、**次のVMDを動かしたまま約0.28秒で再構築**します。
- 同じ待機VMDの通常ループには転送演出を挟みません。選択した待機VMDと再起動時復元も従来どおりです。
- 右クリック → **モーション** → **デジタル転送演出 ON/OFF** で比較でき、設定はローカルに保存します。
- 「デジタル転送演出 ON」が明示されている場合は、Windows側の「アニメーションを減らす」設定によらず転送を行います。アクセシビリティ上、演出が不要な場合はFRAME内でOFFにできます。
- 描画は`pointer-events: none`の透明オーバーレイで行うため、既存のマウス操作を妨げません。描画エラーやモデル変更時は必ず元のキャンバス表示へ戻す設計です。

注意：これは**warpモードの視覚的PoC**です。`MmdCompositeAnimation`などを使う骨格ブレンドはこの実装には含めていません。Windows実機で、雨衣モデルの消失・再出現、クリック透過、切り替え連打、待機復元の挙動を確認してください。

### 2026-10-31: ブレンドとデジタル転送の使い分け（実験版）

アバターを右クリック → 「モーション」 → 「TRANSITION」から切り替え方式を選択できます。選択はローカルの`settings.json`に保存され、FRAMEの次回起動にも引き継がれます。

- 「自動」（初期値）：主要ボーン（胴体、頭、腕、ひじ）のVMDキーフレームを比較し、検証可能な共通ボーンが3つ以上あり、角度差が十分小さい組み合わせだけ約0.4秒ブレンドします。差が大きい・判定できない場合は既存のデジタル転送（約0.26秒消失 → 1秒完全非表示 → 約0.30秒再出現）を使用します。
- 「ブレンド優先」：姿勢の差に関係なくブレンドを試します。短いVMDや1フレームだけのポーズは、その端の姿勢を保ったまま補間します。再生失敗時や完了済みプレビューの自動復帰時はデジタル転送へフォールバックします。
- 「デジタル転送」：これまでの実績ある転送のみを使います。従来の「デジタル転送演出 ON/OFF」も独立して維持しています。
- ブレンドは`babylon-mmd`の`MmdCompositeAnimation`と`MmdAnimationSpan`を使い、元VMDの現在フレームと新VMDの冒頭をクロスフェードします。終了後は新VMDの12フレーム目から再生を継続するため、冒頭を最初から繰り返しません。
- 同じ待機モーションのループは従来どおり直接ループします。保存済み待機の起動時復元、モデル差し替え、音声・表情関連機能は変更していません。

現時点の自動判定は保守的な姿勢差の近似であり、IK・腕と体の干渉を完全には検知できません。Windows実機で手動ブレンド・自動判定・途中連続選択を評価してください。追加の有償素材やMMDファイルの配布はありません。


### 2026-10-31: プログラム生成の歩行（Phase 2 / 実機検証待ち）

右クリック → 「モーション」 → WALK（実験版）で「← 左へ歩く」「右へ歩く →」「歩行を停止」を選べます。単なるその場足踏みではなく、Electronのネイティブアバターウィンドウが左右へ移動します。画面端、モデル変更、手動ドラッグ、サイズ変更、アプリ終了時は移動を停止します。

- `src/walk-vmd.mjs` が、モデルの左右の足IKボーンを検出し、1.2秒の歩行ループをVMDとしてメモリ内生成します。両足の接地・浮き上がり、腕振り、上体・腰の向き、軽い上下動を含みます。外部のVMD・MMDモデル・C++バイナリは同梱しません。
- 接地中は足IKが一定速度で後ろへ動き、その歩幅をモデルの表示スケールからピクセル毎秒に換算して、ウィンドウの横移動と同期させます。OS／描画のフレームレート差、速度上限、骨格の個体差から、完全な足滑りゼロを保証するものではありません。
- 左右の足IKを持たないモデルでは歩行を開始せず、待機モーションへ復帰します。旧来のVMDライブラリ、待機設定、クロスフェード／デジタル転送を保持します。
- 最初のPoCは手動左右歩行のみです。自動徘徊、歩く方向の自動決定、障害物・他ウィンドウへの接地、走行やジャンプは未実装です。
- 発想・設計参考：MIT Licenseの [MikuMikuDesktopPerch](https://github.com/closeberry/MikuMikuDesktopPerch)、特に `docs/MotionRules.md` および `src/GeneratedMotion.cpp`。FRAME側の歩行生成はJavaScriptで新規実装しており、DirectX/C++ライブラリは追加していません。
- 確認ポイント：先生の実機モデルで足IKの追従、左右の向き、腕・衣装の貫通、足滑り、画面端停止、ドラッグ中断、待機への戻りを検証してください。

PoCの動きや実機環境により補正が必要です。公開配布する前にライセンスと対応PMXモデルの再検証を行います。


### 2026-10-31: 全画面透明オーバーレイと独立クリック判定

画面全体を覆う透明なElectron `BrowserWindow` を採用し、内部の小さな `#avatar-stage` にWebGLモデル・デジタル転送・起動演出・モデル選択画面を配置します。全画面の巨大なWebGLキャンバスは作らず、描画負荷は原則アバター周辺に限定します。

- `BrowserWindow.setShape()` による5px単位のネイティブ切り抜きを廃止。WebGLの半透明な輪郭はネイティブ矩形マスクでクリップされません。
- モデルのアルファシルエットを読み取る既存処理は維持し、今後はクリック判定だけに使用。メインプロセスがカーソル位置（WindowsのDIP座標）とローカルのシルエット矩形を比較し、モデル／選択画面上でのみ `setIgnoreMouseEvents(false)`、それ以外は `setIgnoreMouseEvents(true, { forward: true })` で背後のアプリへ操作を通します。
- ヒット判定は約16ms間隔。アルファ輪郭は約200ms間隔で更新します。歩行中の位置変更だけではWebGLと輪郭マスクを再生成しません。
- ドラッグ・ホイール拡大縮小・歩行・画面端での停止・モーションライブラリ・終了時転送は、ウィンドウ位置ではなくアバターステージの仮想座標を使う方式に移行。画面変更時／別モニターへドラッグすると、表示領域全体を対象ディスプレイへ移します。
- キャラクター未選択・モデル読み込み失敗時は、選択パネルの矩形だけをクリック可能にします。モデルを読み込んだらキャラクター部分だけ入力を受け付けます。
- キーボードフォーカスや管理者権限のウィンドウ越しではWindowsによる制約があります。Electron公式: [Custom Window Interactions](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)。

これはネイティブ輪郭ジャギーの原因候補に対する構造的な改善です。まだWindows実機での表示品質・クリック透過・背後のアプリへの操作・負荷は確認していません。性能問題やモデル表示に問題があればIssue #7に記録し、描画／判定を切り分けます。画面をまたぐ自動歩行や複数モデルの同時表示は今後の機能です。


### 描画FPS設定（30 / 60 / 120）

FRAMEの右クリック →「ホーム」→ PERFORMANCE から、描画FPSの上限を 30 / 60 / 120 に変更できます。初期値は60です。選択値は `settings.json` の `renderFrameRate` に保存され、次の起動にも引き継がれます。

- Babylon.js `Engine.maxFPS` を使い、3D描画と同じシーン更新サイクルでMMDのボーン・モーフの評価を実施。VMDの30fpsキーフレーム仕様そのものは変更せず、中間の姿勢は補間します。
- Electronのアバター歩行・ドラッグ更新タイマーも選択値に応じた周期（約33.3 / 16.7 / 8.3 ms）へ切り替えます。移動距離は経過時間に基づき計算するため、FPSによって歩く速度は変えません。
- クリック透過判定（約16ms）とアルファ輪郭解析（約200ms）は独立したままで、選択FPSの影響を受けません。
- 上限FPSは描画を保証する数値ではありません。実際の更新回数はモニターのリフレッシュレート、垂直同期、OSタイマー精度、GPU負荷、Electron IPCのタイミングに依存します。描画とネイティブ移動を同一プロセスの同じ瞬間に完全同期させるものではありません。

### FRAME Motion Lab：歩行の視覚検証（VSCode・AIレビュー用）

右クリック →「診断」→「歩行を撮影して分析資料を生成」で、現在ロード中のローカルMMDモデルに対し、FRAME内蔵の生成歩行を指定姿勢で撮影します。歩行・外部VMDの切替中は停止して待機状態に戻してから実行してください。

- 左右2方向 × 正面・斜め・側面3視点 × 9チェックポイント（VMD F00, 04, …, 32）の合計54枚のPNG、各視点の3×3比較画像6枚を生成します。
- `manifest.json` にはモデルのファイル名、左右の足IKボーン検出結果、歩幅・身長・各フレームの左右足IK座標および接地状態を保存。位置はMMDモデル空間の単位で、画面上のpx座標ではありません。
- `index.html` に比較画像と個別フレームへのリンクをまとめます。VSCodeのAIエージェントにはまず `motion-lab/latest.html` と `motion-lab/latest.json`、必要なら各回の `manifest.json` を確認させてください。

- 開発版はプロジェクト直下の `motion-lab/runs/<date>/` に保存。フォルダはGitの追跡対象外です。公開配布版はユーザーデータ領域の `motion-lab/` に保存します。著作権のあるモデルが映る画像をコミットや公開Issueへ添付しないでください。
- カメラ位置は「観察用」の固定角度。現実の移動距離は含まない、その場足踏みの姿勢比較です。脚の接地・腕振り・体幹回旋の見た目をAIが評価するための資料であり、真の動的物理評価や歩行の滑り量の実測値を自動算出するものではありません。

動作検証: Windows実機での `WebGL canvas → PNG` キャプチャ、正面／側面の見え方、モーション復帰、保存先エクスプローラー表示は別途確認が必要です。異常があれば「診断」の `MOTION LAB` ステータスとアプリのコンソールを確認してください。


### Codex/VSCodeからマウス操作なしでMotion Labを撮影

全画面透明オーバーレイは `setIgnoreMouseEvents()` でモデル外のクリックを背後のアプリへ通します。通常のマウスでは問題なくても、Computer Useの高速なクリックやウィンドウ遮蔽判定では操作に失敗する場合があります。人間向けの最前面表示・クリック透過を変更せずに開発エージェントが撮影できるよう、ローカル専用のターミナルコマンドを用意しています。

1. 最新の `main` を取得して、VSCodeから `npm start` で開発版FRAMEを起動。モデルを読み込み、歩行や外部モーションを止めて待機状態にする。
2. 別のVSCodeターミナルで `npm run motion:lab:request` を実行。FRAMEの設定画面やアバターはクリック不要です。
3. FRAMEはモデル読み込み／保存済み待機の復元完了後に撮影依頼を受け、左右54枚と比較シート6枚をローカル生成します。コマンドは完了を待ち、ギャラリー・JSON診断・レビュー手順のファイルパスを出力します。
4. Codexには `motion-lab/latest.json`、`motion-lab/latest.html`、出力フォルダ内の `REVIEW_GUIDE.md` を確認させ、改善前後の同じフレーム番号を比較させます。

仕組み: 開発版のみ `motion-lab/requests/<UUID>.request.json` を約700msおきに確認し、10分以内の正しい `capture-walk` 要求だけを処理。結果は `<UUID>.result.json` へ返却。すべてローカルファイルで、ネットワークAPI・外部コマンド実行・モデル画像のGit送信はありません。Git除外済み。公開パッケージではコマンド受付を無効化します。

コマンドで開始した撮影はエクスプローラーを自動起動しないので、Codexの操作フォーカスを乱しません。モデル未ロード・撮影失敗・タイムアウト時はターミナルにエラーを出します。Windowsでの実動作はまだ未検証です。
