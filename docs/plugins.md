# FRAME ローカルプラグイン（第一・第二段階）

このページは、[ADR-0002](adr/0002-frame-core-plugin-architecture.md)の試作実装について説明します。

## 対象範囲

- FRAMEの右クリック操作パネルに「拡張」タブを追加。
- ユーザーデータの `plugins/` 配下で、対応する `plugin.json` を持つプラグインを検出。
- 利用者が「利用を許可する」を選んだものだけ実行。プラグインのスクリプトSHA-256が変われば再許可が必要。
- 第一期の `frame.windows-list.v1` はウィンドウ名・PIDの一覧に対応。旧v0.1プラグインはそのまま利用可能。
- 第二期では同形式に任意の `captureEntry` と `window-capture` 権限を追加し、**ユーザーが選んだウィンドウだけを手動撮影**できる。
- FRAME操作パネルでPNGをプレビュー。画像ファイルの自動保存、カメラ、マイク、ChatGPTへの画像送信、MCP連携は**未実装**。
- FRAMEの音声読み上げ・MMD表示・モーションは既存のまま。

## インストール手順（研究所向け）

1. FRAMEの「拡張」タブで「フォルダを開く」を押す。
2. 開いたディレクトリに、別途提供される研究所用プラグインをフォルダごと配置する。GitHubの公開リポジトリには研究所専用視覚スクリプトを同梱しない。
3. 「再読み込み」を押し、プラグインの説明を確認して「利用を許可する」を押す。
4. 「窓一覧を取得」を押す。通常の可視ウィンドウのタイトルとPIDが操作パネルに表示される。
5. v0.2プラグインの場合、対象のウィンドウ名を選択して「選択した窓を撮影」をクリック。取得できたPNGはFRAMEの操作パネル内でのみ表示される。
6. 「画像を消去」を押すかメニューを閉じるとプレビューを破棄する。停止するときは「無効化する」。再起動後は許可状態を復元するが、スクリプト変更時は再許可が必要。

以前のv0.1を使っている場合は、**FRAMEを更新して起動した後に**同名の `frame.vision.windows` フォルダ内の2ファイルを上書きし、`capture-window.ps1` を追加する。プラグインを「再読み込み」すると、新しい撮影権限は未許可になるので再許可する。

Windows PowerShellが必要です。Windows以外の環境ではプラグインの読み込みはできますが、窓一覧取得は無効になります。

## プラグインの構造（研究用v1）

```text
%APPDATA%/(FRAMEのElectron userData)/plugins/
└── frame.vision.windows/
    ├── plugin.json
    ├── list-windows.ps1
    └── capture-window.ps1       # v0.2のみ
```

`plugin.json` の必須形式:

```json
{
  "id": "frame.vision.windows",
  "name": "視覚 / ウィンドウ一覧",
  "apiVersion": 1,
  "type": "frame.windows-list.v1",
  "entry": "list-windows.ps1",
  "captureEntry": "capture-window.ps1",
  "permissions": ["window-titles", "window-capture"]
}
```

安全性のため、現行ホストはこのプロトコル、固定名 `list-windows.ps1` と `capture-window.ps1` のみを受け付けます。任意のJSモジュールをElectronメインプロセスへ `require` する構造ではありません。

- 一覧取得は10秒・256KiB上限。撮影は15秒・12MiB標準出力上限、PNG本体8MiB上限。
- ホストは旧v0.1の単一スクリプトSHA-256の許可情報を維持。撮影対応v0.2ではマニフェストと両スクリプトをSHA-256で検証し、ファイル変更時には再許可が必要。
- 撮影スクリプトは対象HWNDとPIDの一致、ウィンドウの可視状態とサイズを確認し、`PrintWindow` で取得して最大1600×900に縮小する。
- **一部のGPU描画アプリ・保護された画面・最小化ウィンドウは取得できない、または黒く映る可能性がある。** 別の画面を撮って偽装するフォールバックは行わない。

ただし、**許可したPowerShellスクリプトはログイン中のWindowsユーザー権限で動作します**。これはOSレベルのサンドボックスではありません。信頼できないプラグインを導入しないでください。将来の一般配布向けには署名、実行権限分離、アクセス制御等の設計が必要です。

ユーザーが見たウィンドウ名・PID・PNGプレビューはメモリ内にのみ保持します。画像はプレビュー削除・メニュー閉鎖時に破棄し、許可状態だけを `frame-plugin-permissions.json` に保存します。ChatGPTや外部サーバーへ送信しません。

## 次の開発段階

- 実際のWindows端末で表示の可用性と負荷を確認。
- `capture_window` のローカルプレビューは試作済み。実機による撮影品質・例外処理の検証が必要。
- `capture_display`、`capture_camera`、ChatGPT連携は今後の別課題。
- ChatGPTからの呼び出しはFRAMEのプラグインAPIとは独立した接続アダプターとして扱う。
- Coreと視覚機能を物理的に分離し、公開版に視覚プラグインの実装を入れない方針を維持する。
