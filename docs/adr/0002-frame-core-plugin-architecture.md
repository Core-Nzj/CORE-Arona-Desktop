# ADR-0002: FRAME Coreと選択式プラグインによる拡張アーキテクチャ

- ステータス: **採用（Accepted）**
- 決定日: 2026-10-31
- 対象: CORE-Arona-Desktop / FRAMEの製品構成・一般配布方針
- 実装状況: **設計方針を採用。汎用プラグイン基盤は未実装**
- 関連: [Issue #4: FRAME local MCP integration and public plugin distribution](https://github.com/Core-Nzj/CORE-Arona-Desktop/issues/4)、[ADR-0001: ローカル共通Encoder＋用途別Head](0001-local-encoder-multihead.md)

## 決定

**FRAMEは、まず「通常Chatの回答を自動で音声読み上げするデスクトップアプリ」として単独で完成させる。** その後、AviUtlのように利用者が必要な周辺機能を個別に追加できる**プラグイン方式**へ発展させる。

FRAME本体にすべての能力を組み込まない。視覚・PC操作・感情推定・音声入力などは独立した拡張候補とし、ユーザー自身が必要なものを選択できるようにする。

| 構成要素 | 責務 | 方針 |
| --- | --- | --- |
| **FRAME Core** | ChatGPT通常Chatの回答取得、自動音声読み上げ、読み上げ制御、既存の3Dアバター表示・基本設定 | 配布する本体。拡張機能なしでも主要用途を成立させる |
| **FRAME Plugin System** | プラグインの検出、導入・有効化・無効化、互換性判定、権限管理、拡張API | Coreの基盤として段階的に整備 |
| **FRAME Plugins** | 視覚、PC操作、感情推定、音声入力など追加能力 | 本体から分離し、個別導入・個別配布できる構造を目指す |

既存の音声エンジン連携やMMD表示は維持するが、特定の有償音声ソフト・モデル・素材をFRAME本体の配布物に同梱しない。利用者が使用権を持つローカル環境・素材を設定する。

## 最優先の製品価値

- 最初の完成目標は、**ChatGPTの通常Chatで生成された回答を、ユーザー操作の負担を増やさず自然に自動読み上げできること**。
- 通常Chatからの回答取得は、既存のブラウザ拡張など、動作検証済みの連携経路を軸にする。**MCP、Work、Codex、ChatGPT Business契約をCoreの動作必須条件にしない。**
- 音声再生の開始・停止、回答の重複読み上げ防止、ストリーミング中の挙動、音声エンジン不在時の扱いを安定させる。
- 高度な拡張機能が未完成でも、Core単体を「完成した自動読み上げアプリ」として配布できる状態を優先する。
- 有料のAI推論APIを必須にしない、ローカルファーストの基本方針を維持する。

## プラグイン設計原則

1. **任意導入**: Coreは個別プラグインがなくても起動・読み上げできる。導入・有効化・削除は利用者が選ぶ。
2. **障害分離**: プラグインの失敗や互換性不一致で、Coreの読み上げ・アバター表示が停止しない。
3. **公開APIの安定性**: バージョン付きマニフェスト、最低限のライフサイクル、互換性確認を設ける。内部実装へ無制限に依存させない。
4. **最小権限**: 画面・カメラ・マイク・ファイル・PC操作・外部通信は用途別に権限を明示し、必要な許可を利用者から得る。プラグインを無条件に信頼しない。
5. **配布の分離**: 本体・プラグイン・第三者のモデル/音声/モーションの配布可否を区別する。ライセンス不明の素材を同梱しない。
6. **接続方式の分離**: FRAME内部の拡張APIと、ChatGPTとの通信方式（ブラウザ拡張、MCP/HTTP等）は別の責務とする。FRAMEプラグインを導入しただけでChatGPTからツール呼び出し可能になるとは扱わない。
7. **段階的整備**: 最初から巨大なプラグイン市場や複雑なSDKを作らず、Core完成後に必要最小限のAPIを定義し、実例を通じて拡張する。

## 視覚機能の扱い

- 画面・ウィンドウ・カメラを読み取る視覚機能は、**FRAME Coreには組み込まず、独立したFRAMEプラグインとして開発する**。
- 当面は研究所内の**非公開・個人向け拡張**として利用する。一般配布物には視覚機能の実装や必要権限を紛れ込ませない（単にUI上でOFFにするだけでは不十分）。
- 技術的には将来配布できるように、Coreとのインターフェース、アクセス許可、配布素材の境界を整理して開発する。
- Laika / OpenAIから承認パートナーとしての案内等が得られ、**実際の公開・審査・利用規約・ユーザープラン条件を確認できた段階**で、視覚プラグインの公開版を別途検討する。承認取得やPlus/Freeでの利用可能性は、現時点では未確定。
- PC操作等の高権限プラグインも、同様にCoreから分離し、必要な同意と制限を設ける。

## FRAMEプラグインとChatGPTプラグインの違い

- **FRAMEプラグイン**: ローカルのFRAMEへ能力を追加するもの。FRAME側での導入・実行・権限管理が必要。
- **ChatGPTプラグイン / MCP接続**: ChatGPT側から機能を発見し、呼び出すための別の統合経路。接続先・認可・プラン・対応チャットの制約を受ける。
- Issue #4の検証では、ローカルMCP InspectorとWorkからの`ping`に成功した一方、**通常Chatからの`ping`は未達**。この接続の制限を、Coreの完成や一般配布全体の阻害要因にしない。
- Secure MCP TunnelやHTTP方式は接続研究の候補であり、採用・無償性・一般ユーザーへの提供可否は未決定。

## 開発順序

1. **Core完成**: 通常Chat連携による自動読み上げを優先して品質・安定性を固める。
2. **最小プラグイン基盤**: 導入・権限・互換性・障害分離の共通仕様を設計し、小規模な実例で検証する。
3. **視覚プラグイン**: 研究所専用の非公開拡張として開発・検証する。
4. **公開拡張の検討**: 承認、法的条件、技術的接続、対象プランが満たせる場合に限り、各プラグインを個別配布する。

## 決定範囲と未決定事項

本ADRで確定するのは、**「読み上げ中心のCore」と「選択式プラグイン」に分ける製品設計思想と優先順位**。

プラグイン形式、プロセス分離方式、SDK、配布・更新システム、公開審査、MCPの接続方式は未決定。実装に入る前に設計と実装計画を提示し、承認を得る。既存の機能を直ちに移動・削除するものではない。
