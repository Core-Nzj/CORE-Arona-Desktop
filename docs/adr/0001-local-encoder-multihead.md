# ADR-0001: ローカル共通Encoder＋用途別分類Head

- ステータス: **採用（Accepted）**
- 決定日: 2026-10-27
- 対象: CORE-Arona-Desktop / ローカルAI判定基盤
- 実装状況: **設計方針のみ決定。未実装**

## 決定

CORE-Aronaの感情・発話意図・態度など、文章から行う複数の**判定**には、原則として「ローカルで動く共通Encoder（文章を特徴量に変換）」と「用途別の小さな分類Head（その特徴量からラベル・スコアを算出）」を採用する。

- 1つのEncoderの推論結果を複数のHeadで共用し、同じ文章の特徴抽出を重複させない。
- 最初の用途は**表情向け感情判定**。次の候補は発話意図・態度・冗談/皮肉など。
- Encoder/Headは交換・追加できる抽象的なインターフェースにし、具体的なモデルにアプリを固定しない。
- 判定は原則ローカルで実行し、会話ごとにクラウド判定APIや汎用生成LLMを必須にしない。
- リアルタイム性を最優先し、モデルの事前ロード、量子化、計測、音声処理との非同期・並列化を検討する。
- 表情の手動選択、既存MMDモーフ制御、まばたき、口パクは引き続き独立した機能とする。

## 採用理由

- 目的の中心が「文章生成」ではなく、高頻度・低遅延な**分類・判定**だから。
- 感情専用モデルを機能数だけ常駐させる方式と比べ、特徴抽出器を共用できる可能性がある。
- Head単位で新しい判定機能を増やしやすく、推論時間・メモリ・精度を機能ごとに評価できる。
- ただし、単一の共通Encoderがすべてのタスクで最高精度になる保証はない。必要なら特定機能のみ専用モデルへ分岐できる設計を維持する。

## 想定フロー

```text
ChatGPTから受信した発話テキスト
             |
      ローカル共通Encoder
             |
       共通の文章特徴量
             |
      +------+-------+--------+
      |              |        |
   感情Head       意図Head   態度Head ...
      |              |        |
  表情選択        演出制御   演出制御
      |
  MMDモーフ（既存の表情コントローラー）
```

## 重要な境界

- **Encoder＋分類Headは原則として自由な文字列を生成しない。**「HuggingFace → ハギングフェイス」のような新規読み生成は、辞書・ルール・必要ならG2P専用モデルなど、**別系統**で処理する。
- Headは任意のラベルを指定すれば使えるものではない。各Headについて適切な学習済み重み、ラベル定義、検証データが必要。新用途には追加学習が必要になる場合がある。
- 文章内の出来事の感情（悲しいニュースなど）と、アロナが表現すべき感情は区別する。
- 音声読み上げの遅延を最小にするため、すべてのHeadの判定完了を発話開始の必須条件にはしない。間に合わない場合のニュートラル表情などフォールバックを設ける。
- モデルの配布ライセンス、商用利用条件、オフラインキャッシュ方法を決定前に確認する。モデル重みやキャラクター素材は無断でGitに同梱しない。

## 今後の検討・作業（未決定）

1. 日本語に対応した軽量Encoderを候補比較し、推論基盤（ONNX Runtime等）を選ぶ。
2. 感情Headの学習済み重み、ラベル体系、検証データを選定する。既存の表情5分類とのマッピングを定義する。
3. 日本語の短文・皮肉・文脈・発話単位で精度を検証する。
4. 端末環境でコールドスタート、常駐メモリ、1文当たりの推論時間、音声までの追加遅延を測る。
5. 高速性と精度の目標を満たした段階で統合する。

「共通Encoder＋用途別Head」という**方式の採用**は確定。製品名や学習済みモデル、個別Headの仕様、導入日程は現時点で未確定。
