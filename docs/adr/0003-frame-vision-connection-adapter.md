# ADR-0003: FRAME視覚接続アダプターと一時画像セッション

- ステータス: **採用（Accepted）**
- 決定日: 2026-10-31
- 対象: 研究所専用のFRAME視覚プラグインとChatGPT等の外部受信先を接続する境界
- 実装状況: **第1・第2工程実装済み、第3工程はChrome受信まで実機確認済み、第4工程はChatGPTへの画像受信を実機確認、第5工程は明示許可による1回限りの自動送信を試作**。第5工程の実機確認は未実施。
- 関連: [ADR-0002](0002-frame-core-plugin-architecture.md)、[視覚プラグイン試作](../plugins.md)、[Issue #4](https://github.com/Core-Nzj/CORE-Arona-Desktop/issues/4)

## 決定

**撮影（Vision）と送信（Connection）を独立させる。** FRAMEは、プラグインから受け取った画像を一時的にメモリで管理し、**利用者が対象と送信先を確認して明示的に許可した一枚だけ**を接続アダプターに渡す。自動保存・自動送信・継続監視は行わない。

接続方式は後から交換できる構造とし、ChatGPT通常Chatで使用できる方式が未確認であることを前提にする。MCP、Work、Codex、Business契約、有料AI APIのいずれもFRAME Coreの必須依存にしない。

```text
  ChatGPT通常Chat / 将来の対応クライアント
                   ↑ （対応可否は経路ごとに実証する）
           Connection Adapter
         （Browser / MCP / 将来の方式）
                   ↑ 明示的な送信許可後のみ
          Vision Session Broker
      （対象・宛先・有効期限・破棄を管理）
                   ↑ 撮影要求
         FRAME Plugin Host / API
                   ↑
     研究所専用 Vision Plugin（非公開）
                   ↑
               Windows
```

## 責務境界

| 部品 | 担当 | 禁止・制約 |
| --- | --- | --- |
| Vision Plugin | 指定されたHWND/PIDの撮影・PNGの返却 | ChatGPTと直接通信しない。ファイルへ保存しない |
| Plugin Host | 既存の許可ハッシュ照合・対象検証・撮影の実行 | 任意スクリプトの無条件ロード、無断撮影をしない |
| Vision Session Broker（新設） | 画像の短期保持、送信同意、期限・破棄、単発送信 | 送信先を勝手に選ばない。画像やタイトルをログ・永続設定へ出さない |
| Connection Adapter（新設） | 承認済みのPNGを特定の受信先が扱える形式へ変換・転送 | 撮影APIやプラグイン実装を直接操作しない |
| FRAME Core | 許可UIと既存の読み上げ・アバターを維持 | 視覚機能や通信先の存在を起動条件にしない |

既存のウィンドウ一覧・撮影・メモリ上のプレビュー・破棄に加え、**独立したBrokerとローカル検証用Adapterが第1工程で実装済み**。第2工程でFRAMEの撮影UI・Plugin Hostとも接続した。既存の `FramePluginHost.state().capture.dataUrl` は試作用の画像表現であり、将来の外部公開APIと同一視しない。

## 権限を分ける

権限は次の三層を混同しない。

1. **プラグイン実行の許可**: 導入したローカルスクリプトをFRAMEで動作させてよいか（既存）。
2. **特定ウィンドウの撮影指示**: どの対象を、いつ撮るか（既存の手動撮影）。外部要求だけでは実行しない。
3. **撮影画像の送信許可**: どの画像を、どのChatGPT会話・受信先へ渡すか（新設）。プラグイン実行許可や撮影指示から自動的に付与されない。

将来「アロナ、VSCodeを見て」と外部側から要求が来ても、初期設定ではFRAME上で要求元・対象・送信先を提示し、利用者の承認後に撮影・転送する。現在の撮影済み画像を共有する場合も、送信先を示して別途承認する。権限確認を省略する常時監視モードは設けない。

## 一時画像セッション（v1契約案）

- セッションは `requestId`（推測困難な乱数ID）、`source`、`target`（pluginId / windowId / PID）、`destinationId`、`capturedAt`、`expiresAt`、`status`、PNG本体を持つ。
- `status` は `pending -> captured -> approved -> delivered`、または任意段階から `revoked / expired / failed`。承認前の画像はアダプターへ渡さない。
- 同時セッションは原則1件。画像は原則1枚、上限は既存プラグインのPNG 8MiBを超えない。プロトコル変更はバージョン管理する。
- 許可は**画像1枚・送信先1か所・送信1回**に限定。新たな再撮影には再承認が必要。
- 撮影後60秒を過ぎたら未送信画像と許可を自動失効する（実装時に実測で調整可）。明示消去、プラグイン無効化、パネル終了、アダプター切断時は速やかに失効させる。
- PNG本体はRAM中のみで処理する。自動保存・履歴DB・一時PNGファイル・画像内容を含むログは作成しない。ただしOSのページング・クラッシュダンプ等による物理ディスク書き込みは保証の対象外。
- 受信先に必要ないウィンドウタイトル・PID・ローカルパスは送らない。画像に機密情報が映り込む可能性は利用者へ明示する。

※Broker内部の受け渡し権限は60秒で失効します。ただし**従来のローカルプレビュー画像自体は60秒では消えず**、手動消去またはパネルを閉じたときに破棄されます。

## アダプターの内部契約（v1案）

- `getCapabilities()`: その接続方式が画像の送信・受信を扱えるか、許可が必要かを報告する。
- `deliver({ requestId, destinationId, mimeType: "image/png", imageBytes })`: Brokerが認可した画像だけを受け取る。内部ではBuffer等のバイト列を使い、外部プロトコルへのBase64変換はアダプター境界で行う。
- `cancel(requestId)` / `disconnect()`: 承認や転送を取り消し、一時参照を解放する。
- 成功は「相手側が受信した」と確認できた場合に限って表示する。通信開始だけで「ChatGPTが見た」とは表示しない。
- 接続不可・送信失敗なら失敗を明示し、**代替の外部送信を自動実行しない**。画像内容、認証トークンをエラー表示やログへ出さない。

接続アダプターは画像の意味理解を実装しない。解釈はChatGPT等の受信側に任せる。

## 接続方式の優先順位と未検証点

1. **内部インターフェース + ダミー受信先**: 画像の認可・受け渡し・失効・破棄をローカルのみで確認。ネットワーク通信不要。
2. **通常Chat向け候補の検証**: 既存のブラウザ拡張との連携も候補。ただし、ChatGPT画面への画像添付/認識が現在のブラウザで成立するかは**未実証**。実現可能性が確認できるまで採用しない。
3. **MCPアダプター（任意）**: Inspector等での試験を独立して行う。Issue #4ではMCPのpingがInspectorとWorkで成功、通常Chatでは未成功。画像のMCPツール結果が通常Chatへ届くことは**未確認**。
4. 受信先にリモートMCPが必要な場合、公開するネットワーク経路・アカウント/プラン・審査・トンネルの安全性と費用は別途検証する。ローカルMCPを作るだけではChatGPTから自動的に使えるようにならない。

接続方式の選定は技術実証後。これらの候補をFRAMEの必須依存にしない。

## 接続境界のセキュリティ条件

- 将来ローカルHTTP等を使う場合は、標準でloopbackのみにバインドする。LANやインターネットへ公開しない。
- 起動ごとに生成した一時認証情報で送信元を認証し、Origin・宛先・対象を検証する。トークンをURL、ログ、Git、設定ファイルへ書かない。
- 不明な要求元は拒否。要求受信と画像送信は別動作であり、外部コマンドだけで画面撮影を始めない。
- 時間制限、画像サイズ上限、1件ずつの処理、重複要求IDの拒否、セッション取消を設ける。
- FRAMEの公開リポジトリには研究所用撮影スクリプト・秘密鍵・プライベート認証情報を収録しない。

## 実装の分割と完了条件

1. **第1工程（実装済み）**: BrokerとダミーAdapterを独立モジュールとして追加。既存の撮影UI・TTS・MMDに影響させない。
2. **第2工程（実装済み）**: 送信許可UIと一回限りのローカル受け渡し操作を追加。送信先/画像/拒否を確認できること。
3. **第3工程**: 選んだChatGPT接続経路を小さく実証した後、その方式専用Adapterを追加。
4. **検証**: 未許可では画像が渡らない、許可後は一回のみ、期限切れ・閉鎖・権限取消で失効、失敗時の外部転送なし、PNGファイル生成なし、通常の読み上げ/アバター機能が影響を受けない、を重点テストする。

## 対象外

画像認識モデル/OCR、定期撮影、カメラ、常時画面監視、PC操作の自動化、画像のローカル保存機能、ChatGPT APIの有料呼び出しを本ADRのスコープに含めない。

## 第1工程の実装メモ（2026-10-31）

- `electron/vision-session-broker.cjs`: `VisionSessionBroker`。最大1セッション、推測困難なrequestId、対象・宛先の検証、PNG上限8MiB・寸法チェック、RAM上へのコピー、明示許可（`userConfirmed: true`）、一回限りの非同期配達、60秒失効、取消時のAbortSignal、バッファ参照破棄を実装。期限はテスト用に注入可能。送信中は状態 `delivering` を追加。
- `electron/vision-local-adapter.cjs`: `VisionLocalAdapter`。送信先 `frame.local.sink` に限り、受信・検査・即時破棄を行う。ネットワーク・ファイル保存・ChatGPTへの転送は一切行わない。
- `tests/vision-session.test.cjs`: 未許可送信拒否、宛先不一致、一回限りの配達、競合、送信中の取消、失効、異常PNG、受領失敗を重点検証する。
- APIは **Mainプロセス内向け** であり、外部ツール・ブラウザ・rendererから呼べるIPCは現時点では公開していない。`userConfirmed` フラグ自体は認証機構ではない。第2工程で信頼済みUI操作の送信元検証が必須。
- 届けたことを報告できるのはローカルのダミー受信先まで。ChatGPTが画像を受け取ったという意味ではない。
- V8/OSが破棄済みメモリをいつ回収するか、Windowsのページング・ダンプに書かれないかは保証できない。接続アダプターは受信したBufferを保持しない契約とする。

## 第2工程の実装メモ（2026-10-31）

- `electron/main.cjs`: FRAMEの正規設定パネルIPC経由での撮影が成功したときだけBrokerセッションを作成する。メニュー終了・消去・再撮影・拡張の再読込/許可変更・ウィンドウ一覧の再取得時にセッション権限を取消す。`vision.deliverLocal` は見えている設定パネルの認証済みIPCのみ受け付け、要求ID・宛先・確認フラグ・画像保持状態を照合。成功表示はFRAME内部の検証先が受領した場合だけ。
- `electron/avatar-menu.html/js/css`: PNGプレビュー下に送信先、対象画像、残秒数、同意チェック、テスト実行、取消を表示。別画像へ切り替えたらチェックは必ず解除。ローカル受領済み・取消・期限切れは再撮影なしで再送できない。
- テスト実行はネットワーク不使用で、画像の意味理解も行わない。VoiSona、MMD、既存の読み上げ設定は変更しない。Windows実機でのUIと撮影を含む確認は別途必要。

## 第3工程: Chrome受信経路の最小実証（2026-10-31）

- `electron/vision-browser-adapter.cjs`: ローカル専用HTTP (`127.0.0.1:32780`)。利用者が明示的に許可した画像についてのみ、256bit乱数の使い捨てコードを発行し、権限あるChrome拡張の `POST /take` に一度だけPNGを返す。認証は `Authorization: Bearer` で行い、URL・ファイル・ログにトークンを置かない。一般WebページOriginは拒否し、CORS公開しない。
- `electron/main.cjs`: 第2工程のローカル受信先とは別のBrokerで受け渡しセッションを管理。撮影後にFRAMEの拡張タブで専用チェックを入れて初めて待機を開始し、従来のローカル受領セッションは失効させる。認証コードだけを明示ボタンでクリップボードにコピー（画像自体はコピーしない）。
- `electron/avatar-menu.html/js/css`: Chrome待機・取り消し・使い捨てコード表示を追加。ブラウザへの切り替え中は、受信待機に限りフォーカスアウトによるパネル自動閉鎖を保留。×・Escで閉じれば取消。60秒でBrokerが失効。
- `experiments/vision-chrome-receiver/`: 独立した最小Manifest V3拡張。コードを手入力/貼付したときのみFRAMEから画像を取得し、拡張内でプレビューする。自動撮影、ChatGPT画面への添付、自動投稿、ファイル保存は行わない。
- `tests/vision-browser-adapter.test.cjs`: 使い捨て認証、Origin/Host不一致拒否、取消、期限切れを重点検証する。
- 既存の通常Chat自動音声読み上げ拡張には手を加えない。今回実証したいのは **FRAME→Chrome拡張のローカル画像受け渡し** まで。Chrome拡張→ChatGPTの会話入力への画像添付/認識は、この実機検証に成功した後に検討する。画像はページング・ブラウザ内部キャッシュ等のOS側ディスク書込まで保証できない。

### 明確な制約

受領成功は「Chrome拡張へのHTTP応答が完了した」という意味で、ChatGPTが画像を受け取ったことではない。許可なくChromeやChatGPTに画像を自動送信しない。プラグインの非公開PowerShellスクリプトはGitHubには追加しない。

## 第4工程: ChatGPT通常Chatへの添付試行（2026-10-31）

- FRAME→Chrome拡張までは先生のWindows実機でPNG受信とプレビュー表示に成功した。第4工程はChrome拡張からChatGPTの**入力欄に画像を添付する**実験で、ChatGPT側の実機確認は未実施。
- `experiments/vision-chrome-receiver/manifest.json`: `activeTab`＋`scripting` だけ追加。全サイトの自動読み取り権限、常駐コンテンツスクリプト、ChatGPTドメインの恒久的な権限は使用しない。ローカル受信先の権限は従来どおり。
- `chatgpt-attach.js`: 添付先を `https://chatgpt.com` に限定。先生が選択した通常会話の入力欄に対し、メモリ上で生成したPNGの `File` と `DataTransfer` を使い、既存のファイル入力の `change` を優先して試す。入力が見つからない場合だけドロップ操作を試す。メッセージ送信は一切行わない。
- `popup.js/html/css`: 受信画像を拡張内RAMに一時保持し、受信後に追加の送信先・画像確認チェックを要求する。「ChatGPTの入力欄へ添付」ボタンがクリックされたときに限り、アクティブなChatGPTタブへ一度スクリプトを挿入する。画像はOSのクリップボードにもファイルにも置かない。拡張の小窓を閉じる・「画像を消去」で拡張側の一時参照を破棄する。Chrome MV3のCSPに合わせて外部CSSファイルへ分離。
- `tests/vision-chatgpt-attach.test.cjs`: 注入先ドメイン・通常会話入力の存在・PNG検証・ファイル入力イベント・ドロップ代替・ユーザー同意と権限の最低限の契約をテスト。
- 注意: `input.files` の更新や合成ドロップイベントは、ChatGPTの画面実装により無視される可能性がある。技術的にイベントを発行できても「ChatGPTが画像を受け付けた」ことの保証にはならない。**画像サムネイルがChatGPT入力欄に現れたかを先生が確認する。**
- 注意: 添付操作の時点でChatGPT側への画像アップロードが開始される可能性がある。チェックにはその旨を明記する。送信ボタンの自動操作や、隠れた非公開APIへの直接リクエストは行わない。

## 第5工程: 明示承認済み画像だけの単発送信（2026-10-31）

- `experiments/vision-chrome-receiver/chatgpt-send.js`: 初回に入力欄の文章・添付・送信可能な未送信内容を確認。既存内容があれば拒否する。
- 新設の「画像を添付して送信（1回）」ボタンは、既存の「添付のみ」とは別の確認チェックを必要とする。撮影時の許可だけでChatGPTに投稿することはない。
- `chatgpt-attach.js` によって画像の添付を試みた後、同一タブ・同一会話URL・本文空欄を再検証する。`FRAME-vision.png` の添付証跡とChatGPTの送信ボタン有効化を最大15秒待ち、両方確認できた場合のみボタンを1回クリックする。
- 非公開APIへの直接送信、Enterキーの代替押下、失敗時の自動再送、ブラウザ側の画像ファイル保存は実装しない。プログラム側のボタン押下はサーバー側での受信完了を証明しない。
- `tests/vision-chatgpt-send.test.cjs`: 既存文章・添付・会話遷移の拒否、対象画像がない場合の不送信、正常時の単発クリックを検証。Windows実機では未確認。
- 注意: ユーザーが送信許可を押した時点で、ChatGPTの通信・サーバー保存が発生する。FRAMEとChrome拡張にはファイル保存機能はなくても、ChatGPT側の取り扱いはChatGPTのデータポリシーに従う。
