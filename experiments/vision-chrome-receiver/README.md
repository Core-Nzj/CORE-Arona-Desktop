# FRAME / Vision Receiver（研究用 Chrome 拡張 v0.3.1）

FRAMEが撮影したPNGを、使い捨てコードでChrome拡張に受信し、ユーザーが別途許可した場合に限り、開いているChatGPT通常Chatの入力欄への添付を試みます。v0.3では添付のみと、1回限りの「添付して送信」を選べます。自動送信機能の実機確認は未実施です。

## 導入と動作確認

1. Visionブランチで `git pull` → `npm test` → `npm start`。
2. Chromeで `chrome://extensions/` を開く。導入済みの「FRAME Vision Receiver (Research)」を更新（拡張カードの再読み込みボタン）。初回は「パッケージ化されていない拡張機能を読み込む」から `experiments/vision-chrome-receiver` を指定。
3. ChatGPTの添付先となる会話タブ（`https://chatgpt.com/`）を開く。この時点で添付先の会話を選んでおく。
4. FRAMEの「拡張」で対象ウィンドウを撮影。画像と送信先を確認し、「CHROME BRIDGE」で許可にチェック→「Chrome受信待機を開始」。
5. 「認証コードをコピー」を押す。ChatGPTタブを開いた状態で拡張アイコンをクリックし、コードを貼り付けて「FRAMEから画像を受け取る」。
6. 拡張内に画像が表示される。下の「CHATGPT / ATTACHMENT TEST」に現在のChatGPTタブが表示されていることを確認する。
7. 画像を添付するだけなら従来どおり「添付のみ（送信しない）」を使います。
8. 画像を自動送信する実験なら、別の「この画像だけを現在のChatGPT会話へ添付し、送信する」をチェック→「画像を添付して送信（1回）」をクリックします。
9. 拡張は未送信の文章・既存添付がないことを確認してから画像を添付し、`FRAME-vision.png` が添付されたことと送信ボタンが有効なことを確認して、一回だけ送信ボタンをクリックします。画像準備が確認できなければ送信しません。
10. 拡張の「送信ボタンを押しました」はChatGPTが画像を受理したことの保証ではありません。**送信された画像が会話上に表示されたか確認**してください。

## 権限とセキュリティ

- `http://127.0.0.1/*`：FRAMEの使い捨て画像受信用のみ。実際の通信先は `127.0.0.1:32780` の固定ルート。
- `activeTab` と `scripting`：拡張アイコンをクリックしたアクティブタブへ、ボタン操作時だけ添付処理を注入。常駐content scriptや全サイト権限は不要。
- 注入先は `https://chatgpt.com/` だけに限定する。ほかのサイトでは動かない。
- 受信したPNGは拡張のメモリ上のみ。画像・認証コードをディスク、Chromeストレージ、OSの画像クリップボードへ保存しない。小窓を閉じると拡張側のメモリ参照は破棄される。
- 添付/送信ボタンを押すまではChatGPTへ画像データは渡さない。**添付操作を押すと、送信ボタンを押す前にChatGPT側が画像をアップロードする場合がある**。内容を確認してから許可する。
- 「添付して送信」の承認は「添付のみ」と独立。入力済みの文章、ほかの添付、会話の切り替わりを検出したら送信しない。送信ボタンが有効になるのを最大45秒待ち、対象画像を確認できない場合も送信しない。
- 合成的なボタン操作はChatGPTの画面仕様に左右される。送信後のサーバー受領はまだ実機未検証。誤送信防止のため、Enterキーによる代替送信・連続再送は実装しない。
- 受信画像はPNG最大8MiB。添付操作の繰り返しで重複が発生する可能性があるため、各試行でチェックを入れ直す。
- ChatGPT側の非公開DOM実装が変更された場合、ファイル入力や合成ドロップイベントが無視される可能性がある。拡張は成功を偽装しない。明示的に承認した「添付して送信」操作の場合のみ、条件を満たした送信ボタンを1回クリックする。画像の自動保存は行わない。
- Windowsの仮想メモリ、Chrome内部のディスクキャッシュやChatGPT側のサーバー保存まで「RAMだけ」と保証するものではない。FRAME/拡張は明示的な画像ファイル保存処理を実装しない。
- 既存の読み上げChrome拡張とは別物で、干渉しない。FRAMEの音声/MMD機能への依存はない。

## 困ったとき

- 「現在のタブがChatGPTではありません」：添付したい会話タブを表示した状態で拡張アイコンを開き直す。
- 「入力欄が見つかりません」：ChatGPTの通常会話画面を開き直す。
- 「添付操作を実行しました」でも画像が出ない：ChatGPT側がプログラムによる添付を受け付けなかった可能性がある。まだ添付成功ではないので、画像が見えたことを確認するまで送信しない。
- 一度使用したFRAMEの認証コードは再利用できない。新しい画像を受信するにはFRAMEで再撮影する。

研究用の段階であり、一般配布用の拡張機能ではありません。通常Chatへの自動送信はブラウザのUIを経由しており、公式API接続やMCPではありません。

## v0.3.1: 画像アップロード待機の修正

ChatGPTはアップロードを処理すると一時的なファイル入力を空にすることがあります。従来のファイル名だけの検出に加え、添付前には存在しなかった画像サムネイルも確認します。読み込み中・無効な送信ボタンでは送信せず、条件が約1.2秒安定するまで待ってから1回だけ押します。45秒の期限内に完了しなければ失敗扱いにし、画像検出・送信ボタン・アップロード中表示の診断のみを表示します。画像本体やChatGPT会話の本文は診断へ記録しません。

前回の添付試行でChatGPT入力欄に画像が残っている場合は、**既存の画像を削除してから**新たに送信を試してください。未送信の画像・文章があると誤送信防止のため送信を拒否します。
